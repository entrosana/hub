# Architecture

## One-page summary

entrosana-ai is a single FastAPI process organized into 14 capability modules.
Every mutating operation in every module writes through `app/audit/` to a signed
append-only log.  Anything that calls an LLM goes through `app/dlm/` which pins
the model version, the prompt version, and the retrieval order.  Sync to the
existing CashCtrl bookkeeping platform happens via `app/cashctrl/`.

## The DLM doctrine

A regular LLM is non-deterministic — same input can yield different output.
For back-office work where revisors will examine every entry, that's the wrong
property.  The DLM wrapper enforces:

1. **`temperature 0`** at the API call
2. **Pinned model id** — `claude-sonnet-4-6` (or whatever is current).  Never
   `claude-sonnet-latest`.  The id is part of the audit record.
3. **Pinned prompt version** — prompts live in `app/dlm/prompts/v0.1.0/...`
   as versioned bundles.  Every interaction records which version it used.
4. **Deterministic retrieval order** — RAG-style lookups sort their results
   by a stable key (timestamp, id, hash) so the same query returns the same
   ordering on a re-run.
5. **Signed audit record** — every DLM call writes a row to `audit.dlm_interactions`
   with: input, output, model_version, prompt_version, retrieval_keys, hmac.

Anyone with the right audit access can replay any interaction.  A revisor or
the underlying accountant can verify any decision the agent made.

## Module shape

```
app/<module>/
├── __init__.py
├── models.py        # SQLAlchemy ORM tables for this domain
├── schemas.py       # Pydantic request/response models
├── service.py       # Business logic; calls audit.record() on mutations
├── repository.py    # DB access (read + write)
├── router.py        # FastAPI routes mounted under /api/v1/<module>
└── README.md        # 1-page module overview
```

A new endpoint typically touches:

1. `router.py` — define the route, parse via Pydantic
2. `service.py` — call audit.record(action, before, after), call dlm if AI needed
3. `repository.py` — persist via SQLAlchemy
4. `models.py` — declarative model if new table

## Modules (capabilities)

### identity
Tenants (each school is a tenant), users (staff, parents, students), roles
(school_lead, accountant, agent_operator, parent, student), permissions.  JWT
issuer.  Every other module's queries are filtered by `tenant_id`.

### audit
The append-only signed log.  Every mutating service method calls
`audit.record(actor, action, before, after, reasoning)`.  HMAC chain.  Replayable.

### dlm
Wrapper around the LLM call.  Enforces temperature=0, pinned versions,
deterministic retrieval, audit emission.  All other modules use `dlm.run(prompt,
context)` not the raw Anthropic SDK.

### cashctrl
HTTP adapter to CashCtrl's API.  All booking entries in entrosana eventually
land in CashCtrl too — never replace, always augment.

### accounting
Booking proposals (generated by DLM from documents), bank reconciliation,
amber-zone escalation queue for the accountant.

### admin
Students, parents, staff, classes, organizational hierarchy.

### scheduling
Class schedules, substitute teacher matching, payroll handover.

### contracts
Contract templates, e-signing (Swiss e-signature standard via Skribble or
similar), versioning, status (draft / sent / signed / void).

### expenses
Expense submission (receipts), approval workflow, reimbursement payout.

### taxes
Swiss source tax (Quellensteuer), AHV/IV, payroll tax, year-end forms.

### signup
Student enrollment flow.  Parent applies via public form, school approves,
contracts get sent automatically.

### addresses
Swiss postal address validation (matchpartner / SwissPost API), geocoding.

### billing
Family-based invoicing.  Sibling discounts, multi-stage payment plans,
reductions.

### documents
Document ingestion (email + upload).  OCR (Tesseract / Azure / Claude vision).
Classification (which module owns this doc).  The AI surface — DLM-heavy.

## Cross-cutting

- **Authn**: JWT (HS256, 60min access + 30d refresh) via `identity/jwt.py`
- **Authz**: Pydantic dependencies on each route check `request.user.role`
- **Tenant isolation**: every query goes through `repository.scoped(tenant_id, ...)`
  which adds the filter automatically.  Violations are caught in CI.
- **Tracing**: OpenTelemetry on every request.  Spans include the audit record id.
- **Async jobs**: anything taking >1s goes to Celery (DLM inference, document OCR,
  payroll calc, year-end report gen)

## Deployment

Single Docker image, runs anywhere.  Production target: same EC2 as SYGNIF
initially, can migrate to a dedicated tenant-per-VPC topology later if customer
count grows.
